Une question pour la salle

Dans quel rayon range-t-on cette phrase ?

« Election debate highlights key economic policies. »

politiqueéconomie

Les deux. Personne n'a tort.

Laisser la salle répondre. Certains diront politique, d'autres économie. La bonne réponse est les deux : c'est tout le sujet.
Et celle-ci

Sports, politique, économie ou divertissement ?

« AI will take on the world. »

aucun rayon

Le vide aussi est une réponse.
Le classifieur doit savoir la donner.

Le cas oublié : rien ne s'applique. Un modèle qui force toujours une étiquette se trompe ici.

Deux problèmes qui se ressemblent

Multi-classe

Un texte va dans exactement un rayon. Les classes s'excluent.

Multi-label

Un texte va dans zéro, un ou plusieurs rayons. Le nombre d'étiquettes varie d'un texte à l'autre.

Les étiquettes se tiennent entre elles : la présence de l'une change la probabilité de l'autre.

Élection et économie vont souvent ensemble. Le modèle doit apprendre ces dépendances, pas seulement chaque étiquette isolément.

Le déséquilibre

Certaines étiquettes reviennent partout, d'autres presque jamais. Plus l'écart est grand, plus l'entraînement souffre.

La corrélation

Le modèle doit apprendre les liens entre étiquettes, en plus des étiquettes elles-mêmes.

Rien d'impossible ici, mais du temps et des ressources avant la première prédiction utile.
Rayon 2

Le raccourci

Pourquoi un LLM

Simple

Une API, dans n'importe quel langage. Pas de prétraitement du texte, pas de modèle à entraîner.

Moins cher

Héberger un modèle demande un GPU. Pour des textes courts, payer l'inférence au token coûte moins.

Ajustable

Un ou deux exemples dans le prompt suffisent à relever la qualité des prédictions.

Un token, c'est un morceau de mot. Le modèle de facturation au token change le calcul pour les petites tâches.

« Un LLM ne répond jamais deux fois pareil. »

C'est vrai en général. Sur une tâche de classification simple, la réponse varie rarement.

# on fixe le hasard autant que l'API le permet
temperature=0,
seed=424242,
Le paramètre seed d'OpenAI rend les résultats presque déterministes. Presque : assez pour classer.

Pas de jeu d'entraînement.
Un jeu de test, toujours.

  • Il reflète la complexité réelle du cas d'usage, dans un format constant.
  • Il couvre les combinaisons d'étiquettes, y compris l'absence d'étiquette.
  • Il suit la distribution du réel quand on la connaît.
  • Quelques centaines d'exemples au minimum, davantage à chaque étiquette ajoutée.
  • On le renouvelle avec des données fraîches.
Le LLM dispense d'entraîner. Il ne dispense pas de mesurer.
Rayon 3

Le prix d'une pensée

La règle qui décide de tout

4 mots en entrée
= 1 mot en sortie

Les fournisseurs facturent environ un quart du coût à l'entrée et trois quarts à la sortie. Chaque token généré coûte aussi du temps.

Ordre de grandeur des grilles tarifaires en 2024. Le ratio exact varie selon le fournisseur, l'asymétrie reste.

Trois façons de demander

tokens en entréetokens en sortieschéma, pas une mesure
Chain of thought« réfléchis étape par étape »
raisonnement détaillé
Tree of thoughtstrois experts débattent
débat entre experts
Few-shotquelques exemples, réponse courte
consigne + exemples

Pour classer, on paie les exemples en entrée et on réduit la sortie à une liste.

Chain of thought et tree of thoughts font mieux sur les problèmes durs, au prix de beaucoup de sortie. Si le budget et la latence ne comptent pas, ils restent une option. Pour une liste d'étiquettes, le few-shot gagne.
Rayon 4

Le classifieur

Le prompt few-shot

API OpenAI, extrait
messages = [  {"role": "system", "content": "You are a multi-label classifier. Return the tags "   "as a list separated by commas. If no tags apply, return nothing. "   "Available tags: sports, politics, economy, entertainment."},  # exemple 1 : deux étiquettes  {"role": "user", "content": "Text: 'Election debate highlights key economic policies.'"},  {"role": "assistant", "content": "Tags:politics,economy"},  # exemple 2 : aucune étiquette  {"role": "user", "content": "Text: 'AI will take on the world.'"},  {"role": "assistant", "content": "Tags:"},  # le texte à classer  {"role": "user", "content": f"Text: '{content_txt}'"},]

Deux exemples suffisent à fixer le format de la réponse, et le cas vide.

Choisir les exemples est la partie difficile : ils apprennent au modèle la structure de la tâche et le format de sortie. Le deuxième exemple montre qu'une réponse vide est permise.

Ne jamais croire la sortie sur parole

extrait condensé
ALLOWED = ["sports", "politics", "economy", "entertainment"] def parse_labels(completion) -> list[str]:    text = completion.choices[0].message.content    text = text.replace("Tags:", "").strip()    if not text:        return []    labels = [label.strip() for label in text.split(",")]    return sorted(set(labels) & set(ALLOWED))   # le garde-fou

Le modèle peut inventer un rayon. L'intersection avec la liste autorisée l'efface.

On retire le préfixe, on découpe, on nettoie, puis on ne garde que les étiquettes connues. La sortie devient une liste triée, comparable au jeu de test.

Plus de rayons, moins de précision

Avec beaucoup d'étiquettes, le modèle hésite et la précision baisse.

Rayon 5

En production

Garder une trace de chaque appel

  • Tracer l'entrée, la sortie, les tokens et la durée. LangSmith ou Phoenix les affichent.
  • Évaluer en continu sur des données fraîches, par une revue humaine ou par un second LLM qui juge le premier.
  • Versionner chaque prompt avec son rapport de classification, pour comparer les versions sur les mêmes métriques.
LLM as a judge : un modèle relit les sorties du classifieur. Les traces servent aussi à suivre le coût et la latence : une séquence plus longue génère plus lentement.

Un LLM ne supprime pas
le dataset.

Il le déplace
de l'entraînement vers le test.

Le gain est réel : quelques exemples, une API, des jours au lieu de mois. Mais la rigueur reste la même, elle porte sur la mesure : jeu de test, traces, métriques, versions de prompt.
